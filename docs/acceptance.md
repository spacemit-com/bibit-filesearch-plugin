# 功能验收判据

本文按功能项列出**可复现的判据**（怎么测、期望什么），供回归时逐项核对。
每条都对应插件里的一个可观察行为；通用前置见文末。

## 1. 索引配置生效性（排除规则）

| 检查点 | 期望 |
|---|---|
| 在「排除规则」加一行 `skipme` → 保存并索引 → 检索该目录内文件的内容 | 搜不到该文件 |
| 重启服务后再检索 | 仍搜不到（已入库的文件会被回收：保存时与服务启动时各核对一次） |
| 库内核对 | `files` 表里该路径的行数为 `0` |
| 删掉规则 → 保存并索引 | 该文件重新可被搜到 |

判据要点：**配置未变时「保存并索引」是幂等早退**，不会触发回收——所以验证回收必须
真的改动配置。规则写父目录名即可（按路径任一分量匹配）。

## 2. Top-K 是「单次检索最多返回条数」

| 检查点 | 期望 |
|---|---|
| Top-K=3 检索 | 页头「共 N 条匹配」，**N ≤ 3**，列表条数 = N |
| Top-K=20 检索同一个词 | N ≤ 20，列表条数 = N |
| 重启服务后再检索 | 仍按保存的值生效（不会回退出厂默认 5） |

页头计数与列表实际条数**必须相等**。命中本来就比 Top-K 少时数字不变是正常的——
判据是 `N ≤ Top-K`，不是 `N == Top-K`。

## 3. 排序不随 Top-K 变

| 检查点 | 期望 |
|---|---|
| 同一查询词，Top-K 依次设 3 / 5 / 10 / 20 各检索一次 | **前几名顺序完全一致**，各条 `score` 一分不差 |
| 各条名次 `#N` | 对得上；Top-K 小只是少列后几条 |

检索深度（取多少个**块**参与文件级聚合）由后端 `search.candidate_pool` 独立控制
（默认 1000，`0` = 不截断）。若把两者接到同一个值上，调小 Top-K 会让块级窗口收缩、
排在窗口外的文件分数凭空消失——表现为「改显示条数 → 排序变了」。

## 4. 相关度显示为名次 `#N`

| 检查点 | 期望 |
|---|---|
| 每条结果右上角 | 显示 `#1` `#2` `#3` … **名次**，不是 `100%` / `62%` 这类百分比 |
| 悬停该徽标 | 提示「本次检索按相关度排序，这是第 N 位——是名次，不是匹配百分比」 |

后端的 `confidence` 是 min-max 归一化产物：每次检索**头名恒 1.0、末名恒 0.0**，与绝对
相似度无关，同一文件同一查询，结果集多一条垃圾就会改变它的显示值。需要绝对量用 `score`
（未归一化融合分，在同一 embedding 配置内才可比，不要当用户可见指标）。

## 5. 「恢复默认」（两段式确认）

| 检查点 | 期望 |
|---|---|
| 第 1 次点击 | 按钮变红、文案变「再点一次确认」，下方出现说明条；**配置无任何变化** |
| 点说明条上的「取消」 | 立刻回到普通态，不执行重置 |
| 进入确认态后改任意表单字段 | 立刻回到普通态，不执行重置 |
| 等待 / 切页面后回来 | 确认态**不自动消失**（不再有超时兜底） |
| 第 2 次点击 | 执行恢复：绿色提示「已恢复默认配置，正在重新扫描并建立索引」，表单回填默认值 |
| 落盘文件 | 只剩 `config_version: <n>` 一行 |

回填的默认值：知识库路径 `~/Documents`（目录存在才给）、深度 `3`、Top-K `5`、
排除规则 `.git` / `node_modules` / `__pycache__`、20 类全选、自动索引开。

落盘只剩版本号是**稀疏存储的应有形态**，不是配置丢失——用户文件只存与出厂默认不同的键，
生效值看 `GET /api/settings`。

命令行等价验证：

```bash
curl -s -X POST http://127.0.0.1:18700/api/settings/reset | python3 -m json.tool
cat ~/.config/bibit-filesearch/config.yaml          # 期望：仅 config_version 一行
curl -s http://127.0.0.1:18700/api/settings | python3 -m json.tool   # 期望：完整生效值
```

## 6. 语言跟随宿主

| # | 操作 | 期望 |
|---|---|---|
| 1 | 宿主「通用设置 → 语言」选「简体中文」 | 文件检索页中文（保存并索引 / 恢复默认） |
| 2 | 选「English」 | 文件检索页英文（Save & Index / Restore defaults） |
| 3 | 选「系统」（系统语言为中文） | 文件检索页**中文** |
| 4 | 停在文件检索页，去通用设置改语言再切回来 | 无需刷新页面即跟随 |
| 5 | 从未动过语言设置（宿主缺省 = 系统） | 跟随系统语言 |

语言由宿主经 contribution props 下发**已解析的最终语言**（`en` / `zh-CN`），
插件不读宿主 localStorage、不轮询、不自行解析 `'system'`。这条由单测守着
（断言归一化是入参纯函数：中文 navigator 环境下 `'system'` 仍归一为 `en`，
且不再导出任何读环境的函数）。

## 7. 「刷新状态」按钮的点击反馈

| 时刻 | 期望 |
|---|---|
| 点击瞬间 | 立刻变「⟳ 正在刷新…」；按钮禁用，再点无效 |
| 约 0.4s 后 | 变「✓ 已刷新」（绿色勾 + 弹入动画） |
| 再约 1.4s | 自动回到「刷新状态」 |
| 服务停掉后点 | 显示「✕ 刷新失败」（红叉），不静默 |

三条设计约束：**busy 有下限**（请求本机只要十几毫秒，不设下限只闪一帧）、
**done 只保持一段固定时长**（刷新不是持续状态，常驻会变噪音）、**点击即进 busy**
（先改 UI 再发请求，否则点下去到返回之间仍然看不到任何变化）。

页面每 2 秒后台轮询做的是同一件事，所以该按钮的增量只是「不必等最多 2 秒」；
轮询带 silent 标志，不播动画。

## 8. 增量索引期间的状态与「待向量化」

前置：服务 active，磁盘上有可拷入的较大文档。

| 步骤 | 期望 |
|---|---|
| 把一批文件拷进知识库目录（或拖一个文件进去） | **5 秒内**状态格变「扫描中」 |
| 看「待向量化」格 | ≥ 1（池中已排队的行立即可见）|
| 「已索引文件」格 | 随后增长 |
| 索引完成 | ≤ 2s 自动回「已完成」，「待向量化」回 `0` |
| 全程 | **不出现**「已处理 x / x（待 0）」这种自相矛盾的进度行 |

两格的口径：

```
待向量化（统计格） = pending = queued + vectorizing
待处理（进度行）   = pending（同一个数）
```

两处**必须一致**。不要把进程内的在飞计数（`inflight`，界面上 0 或 1）加进来——那是重复
计数：同一文件既可能是库里的 `vectorizing` 行、又被计入在飞（库里 8 个文件能算出 9）。
`inflight` 只用来判断「此刻有没有活在干」。

扫描期间状态格下方给出进度：遍历阶段显示「正在遍历文件 x / N」，向量化阶段显示
「已处理 x / N 个文件（待 P）」并带进度条；两个阶段不混排。

命令行核对：

```bash
curl -s http://127.0.0.1:18700/api/scan/progress | python3 -m json.tool
journalctl --user-unit bibit-filesearch -f   # 看 watcher 增量索引 / 目录补扫完成
```

## 通用前置

1. 后端服务在跑且可连：

   ```bash
   curl -s http://127.0.0.1:18700/health          # {"code":0,...,"status":"ok"}
   curl -s http://127.0.0.1:18700/health/deep     # embed 一路为 ok
   ```

2. **GUI 已重启**（插件只在 GUI 启动时从系统插件目录同步、验签、解包）：

   ```bash
   ps -eo pid,lstart,cmd | grep '[b]ibit-gui'     # 启动时间应晚于插件安装时间
   ```

3. 界面路径：**设置 → 功能 → 文件检索**。

4. 命令行旁证（不开界面也能核后端）：见 README「故障排查」与后端 `docs/api-contract.md`。
